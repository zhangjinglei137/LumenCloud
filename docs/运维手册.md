# LumenCloud 运维手册（简版）

> 日常运维速查：部署、初始密码、凭据配置、备份恢复、迁移与故障排查。
> 完整设计见 [`新系统设计.md`](./新系统设计.md)，旧流程现状见 [`现状流程梳理.md`](./现状流程梳理.md)。

---

## 1. 部署（零 .env 开箱即用）

Phase 8 起无需任何环境变量：凭据在 Web 设置页配置入库，JWT 密钥与 admin 密码首启自动生成。

### 开发 / 本地

```bash
docker compose up -d --build          # 内置 db（PostgreSQL 16）+ lumencloud
访问 http://localhost:8000
```

### 生产（Docker Hub 镜像）

```bash
# 打 tag 触发 GitHub Actions 构建多架构镜像并推送 Docker Hub（需 Secrets: DOCKERHUB_USERNAME/DOCKERHUB_TOKEN）
git tag v1.0.0 && git push origin v1.0.0

# 服务器上部署（无需 .env.prod；IMAGE_TAG 缺省 latest）
IMAGE_TAG=1.0.0 docker compose -f docker-compose.prod.yml up -d
```

- 数据卷：`./pgdata`（PostgreSQL 数据）、`./data`（JWT 密钥文件 `.jwt_secret` + 备份目录）
- 应用启动时 **alembic 自动迁移建表**（`init_db`），无需手工初始化
- 健康检查：`GET /api/health`（应用）/ `pg_isready`（数据库）

## 2. 初始 admin 密码获取

首启无 admin 用户时自动创建，随机 16 位初始密码**只打印一次在服务日志**（唯一渠道）：

```bash
docker compose logs lumencloud | grep 初始密码
docker compose -f docker-compose.prod.yml logs lumencloud | grep 初始密码   # 生产
```

拿到后：登录 → 设置页改密码（或 `POST /api/auth/change-password`）。
用户名默认 `admin`，如需覆盖可在 compose `environment` 设 `INIT_ADMIN_USERNAME`（可选）。
> ⚠️ 密码在日志中仅出现一次；若错过，可清空数据库重启重新生成（见 §5），但会丢失现有数据。

## 3. 设置页凭据配置

登录后 → **设置** →「服务凭据配置」，逐项填写并「保存全部」：

| 服务 | 需配置项 |
|------|---------|
| TMDB | `tmdb_api_key`（代理可选） |
| Emby | `emby_base_url`、`emby_api_key` |
| cloudSaver | `cloudsaver_base_url`、`cloudsaver_username`、`cloudsaver_password` |
| AList | `alist_base_url`、`alist_token` |
| aria2 | `aria2_rpc_url`、`aria2_token` |
| NasTools | `nastools_base_url`、`nastools_username`、`nastools_password` |
| PushPlus | `pushplus_token`（可选，缺省仅站内通知） |
| 夸克 | `quark_default_folder`（转存目标目录）、`quark_quota_gb`（容量配额，默认 10） |

- 凭据保存在 `system_config` 表，**PATCH 保存即生效，无需重启**（进程内缓存自动刷新）
- 敏感项 GET 回显 `***` 占位，**绝不回显明文**；未改动/留空/仍为 `***` 的字段不会提交，避免误清空其他服务凭据
- 环境变量仍可作为 fallback（`system_config` 缺失时回退），旧部署迁移无需重建

## 4. 备份 / 恢复

### 备份

```bash
docker exec lumencloud python scripts/backup_db.py        # 默认保留最近 14 份，输出到 scripts/backup/
docker exec lumencloud python scripts/backup_db.py --keep 30
```

- SQLite：`sqlite3 .backup` 在线安全备份（对运行中库也安全）
- Postgres（当前 compose 默认）：打印 `pg_dump` 指引（容器内不自动执行）
- 宿主 cron 建议：`0 3 * * * docker exec lumencloud python scripts/backup_db.py`

### 恢复

- SQLite：停服后用备份文件替换 data 目录下数据库文件，再启动
- Postgres：按 `pg_dump` 指引导入到 `pgdata` 卷对应库，再重启 lumencloud
- 备份与回滚共用 `scripts/backup/` 目录（迁移备份 `media_export_*.json` 同处）

## 5. 数据库迁移（Alembic）

- 建表/变更全部走 `backend/alembic/versions/` 手写迁移，**应用启动时自动 `upgrade head`**，一般无需手工干预
- 手动执行（容器内）：

```bash
docker exec lumencloud alembic upgrade head    # 升级到最新
docker exec lumencloud alembic current         # 查看当前版本
```

> 从旧 n8n 迁移数据用 `docker exec lumencloud python scripts/migrate_from_n8n.py --dsn postgresql://...`（一次性，幂等可重复执行）。

## 6. 故障排查

### 6.1 转存被「陌生 aria2 任务」阻断（GID 来源校验告警）

现象：队列任务保持 pending，日志/通知出现「检测到陌生 aria2 任务（无本系统 GID 来源标记），暂停转存」类告警。

原因：转存前校验 aria2 `active + waiting` 队列，存在不带本系统来源标记（`comment="lumencloud:<media_id>:<episode>"`）的任务即本轮跳过并告警——这是冷切换兜底，防 n8n 或其他工具误启动导致双转存。

处置：
1. **确认 n8n / 其他下载工具已停止**（LumenCloud 运行期间 n8n 必须保持停止，铁律：双系统定时绝不同开）
2. 检查 aria2 当前活动/等待任务来源：确认均为本系统产物，若存在**陌生任务请人工清理**（在 aria2 客户端 `aria2.remove`/`forceRemove` 对应 GID；勿手动删除还在下本系统任务）
3. 清理后下一轮兜底 tick 自动恢复转存，无需重启

### 6.2 夸克 /quark 残留文件

正常流程「下载完成即释放」（transfer 完成后 alist 删除）；另有每 12 小时兜底清理（`release_space_cleanup`）扫描 `/quark` 中不受任何任务引用的孤儿文件并删除。

若残留仍在或需手工处置：
1. alist 列出 `/quark`：`GET /api/fs/list?path=/quark`
2. 核对文件是否被进行中任务引用（队列页 transferring/downloading 任务）
3. 未引用则删除：`POST /api/fs/remove`（或 alist 界面操作）

### 6.3 转存/下载卡住

- 任务超时（默认 2h 无进展）由启动恢复 `recover_on_boot` 回退 queued 重试（重试前清理夸克残留）
- 长时间无进展且未回退：重启 lumencloud 容器触发恢复逻辑；仍失败 → 队列页人工 retry（`POST /api/queue/{id}/retry`）

### 6.4 转存无 success / 等待落盘超时 → 先验 folderId（Q1）

现象：队列任务反复 failed，日志出现「转存后等待落盘超时（300s）」；夸克里实际有文件，但 alist `/quark` 下看不到；下载器 aria2 无任务（`download_task` 无记录）。

根因链：设置页 `quark_default_folder`（cloudSaver save 的 folderId，决定文件转存到夸克哪个目录）≠ alist Quark 驱动 `root_folder_id`（决定 alist `/quark` 挂载的是夸克哪个目录）→ 文件落盘到夸克**其他目录** → transfer 轮询 `/quark/{文件}` 永远不可见 → 300s 超时 → retry 3 次后 failed。

处置：
1. **设置页 → 服务凭据配置 → 夸克网盘组点「验证 folderId」按钮**，直接看诊断结论（注意：验证的是已保存的配置，刚修改请先「保存全部」）；
2. 若提示不一致：把诊断里显示的 **AList root_folder_id** 复制填入设置页 `quark_default_folder`，点「保存全部」（保存即生效，无需重启）；
3. 手工核对方法（服务器上）：
   ```bash
   curl -H "Authorization: <你的alist令牌>" http://<alist地址>/api/admin/storage/list
   ```
   在返回中找到 `driver` 为 `Quark` 的条目：`addition`（JSON 字符串）里的 `root_folder_id` 即 alist 侧挂载的夸克根目录；同时确认其 `mount_path` 为 `/quark`（若挂在其它路径，转存链路同样不通，需在 alist 调整挂载点）；
4. 修正后重跑 scan（或对失败的队列任务点 retry），预期：日志出现「转存并提交 aria2 下载」、队列页出现 downloading、`download_task` 有记录。

### 6.5 其他

| 现象 | 检查 |
|------|------|
| 影视不巡检 | 设置页 `scheduler_enabled` 是否开启；单影视 `status` 是否为 paused/error；Emby 是否可达 |
| 定时任务全部不运行（总开关已开） | A-2 统一语义：总开关开启后 job 级**未配置即默认跟随开启**；请检查是否误写了 `scheduler.<job_id>=false`（`GET /api/settings` 回读 `scheduler.*` 键核对），或 job 开关读取失败被 fail-closed 暂停（见服务日志 `[scheduler]` 告警） |
| Emby 未收录剧集被跳过 | 属默认防盲入行为，可配置为不跳过（跳过防重检查、任务照常执行） |
| 找不到初始密码 | 见 §2；数据库已存在 admin 用户时不会重新生成（可手动 `UPDATE users` 重置，或清库重来） |
| 服务凭据不生效 | 确认已在设置页保存且非 `***` 占位；`GET /api/settings` 的 `services` 各服务是否 `true` |
| 影视卡在 paused / downloading 无法恢复 | B-1 语义：有进行中任务时设置页暂停会被 409 拒绝（提示等任务完成）；无任务时手动 `PATCH /api/media/{id}` status=tracking 恢复巡检；仍异常则查 recover_stale 是否被关闭（scheduler.recover_stale） |
| 所有账号登录突然失效（强制下线） | 属 jwt_secret 轮换后的正常行为（见 §7.4）：删除 .jwt_secret 重启会注销全部会话；如需保留登录请勿删除该文件 |
| 启动失败 / alembic 迁移报错 | 查 `alembic current` 与代码版本链（backend/alembic/versions/）；**勿修改历史迁移文件**；迁移失败常见为唯一约束冲突（如 0006 tmdb_id 重复数据，迁移会先清理保留最早一条），可先手工清理重复后再 `alembic upgrade head` |
| 备份是否可用 | 建议每月恢复演练（§4 恢复流程）；SQLite 备份见 `scripts/backup_db.py --keep N` |

## 7. 定时任务与维护配置

### 7.1 定时任务启用步骤（G-1.1，A-2 语义）

- 总开关：设置页「定时调度总开关」`scheduler_enabled`（未配置默认开启）；**job 级未配置时默认跟随总开关**（打开总开关即全部定时运行）
- 单独关闭某 job：设置页/`PATCH /api/settings` 写 `scheduler.<job_id>=false`；单独强制开启写 `=true`
- 8 个 job（全部注册即暂停，由上述开关恢复）：

| job_id | 触发 | 职责 |
|------|------|------|
| scan_all_media | 每 1 分钟 tick | 按各影视 last_scan_at 到期过滤巡检 |
| process_transfer_queue | 每 1 分钟 | 转存队列兜底消费（事件/手动触发为主） |
| nastools_sync | 每 1 小时 | NasTools 目录同步兜底（下载完成事件为主） |
| release_space_cleanup | 每 12 小时 | /quark 孤儿文件清理 |
| notification_scan | 每 5 分钟 | 通知扫描 |
| recover_stale | 每 1 小时 | 超时（默认 2h 无进展）任务回退 |
| capacity_alert | 每 1 小时 | 容量快照 + 使用率告警 |
| prune_history | 每 1 天 | task_run/容量快照历史清理（见 7.2） |

- 验证已生效：`GET /api/settings` 回读 `scheduler.*` 键；服务日志 `[scheduler] 已启动 N 个 job`

### 7.2 task_run 历史清理（G-1.4，D-1）

- `prune_history` job 每日清理：`task_run`（按 started_at）与 `quark_capacity_log`（按 checked_at），各保留最近 **30 天**（默认）
- 覆盖保留天数：设置页/`PATCH /api/settings` 写 `task_run_retention_days`（如 `7`，最小钳制 1 天）
- 手工立即清理：把 `task_run_retention_days` 临时调小并等待次日 job，或直接 SQL（`DELETE FROM task_run WHERE started_at < now() - interval '30 days'`，需自行承担数据不可逆）

### 7.3 quark_quota_gb 与容量（G-1.2）

- 设置页「业务参数」`quark_quota_gb`：夸克中转容量配额，默认 10 GB
- **若真实夸克配额为 210 GB，务必改为 210**：否则容量统计按 10GB 判断，会导致大文件被误拒转存（联动 C-2 分页修复后的准确统计）

### 7.4 jwt_secret 与登录凭据（G-6.2，Q5）

- 首启自动生成并落盘 `<data_dir>/.jwt_secret`（chmod 600），**无需手动配置**；仅用于签发/校验登录 JWT，与用户密码无关（密码 bcrypt 存储）
- 轮换：**删除该文件后重启服务**（重启自动重新生成；旧 token 全部失效，所有用户需重新登录）
- 设置页「服务凭据配置」面板有只读说明

### 7.5 邀请码与注册链接（G-6.3，Q6）

- 设置页「邀请码管理」：生成/删除；行内「复制」「复制注册链接」按钮
- 注册链接形如 `http(s)://<本站地址>/register?code=<邀请码>`——打开后注册页邀请码**自动预填**，直接完成注册
- 表格「使用者/使用时间」显示用户名与格式化时间（不再裸 id/ISO）

## 8. 部署状态卡与验收清单

### 8.1 部署状态卡（G-2，system_config 生效键值速查）

| 键 | 默认 | 说明 |
|------|------|------|
| scheduler_enabled | true（未配置） | 定时总开关；false 全部停 |
| scheduler.<job_id> | 跟随总开关 | 8 个 job 单独开关 |
| scan_interval_minutes | 60 | 全局巡检周期（分钟，media 可覆盖） |
| quark_quota_gb | 10 | 夸克容量配额（GB） |
| capacity_safety_margin_gb | 0.05 | 容量安全余量（GB） |
| capacity_alert_threshold | 0.9 | 容量告警阈值 |
| max_episode_size_gb | 1.5 | 剧集单集大小上限（GB） |
| max_movie_size_gb | 5.0 | 电影大小上限（GB） |
| task_run_retention_days | 30 | task_run/容量快照保留天数 |
| scan_baseline_required | false | Emby 防重基线缺失时是否跳过巡检 |

> 全部经 `GET /api/settings` 回读核对；PATCH 保存即生效无需重启

### 8.2 修复后端到端验收清单（G-1.3）

部署完成后按序验收（前一项通过再进入下一项）：

1. **Q1 配置基线**：设置页「验证 folderId」诊断一致；scan 一部剧 → 日志出现「转存并提交 aria2 下载」、队列 downloading、`download_task` 有记录
2. **A-1 续跑**：一次入队 ≥2 集自动逐集消费；下载完成释放容量后 pending 自动重试
3. **B-3**：模拟超时任务 → recovery 回退后 aria2 任务被移除、CAS 冲突不误杀
4. **B-1/B-2**：下载中点暂停被 409 拦截；删除影视不再产生孤儿数据
5. **C-1/Q12**：Emby 库「加入订阅」→ 巡检入队（未播出集不入队）；卡片「在 Emby 中打开」不空白页（serverId）
6. **Q10/Q6**：审批/通知/邀请码显示用户名；注册链接预填邀请码
7. **Q5/Q9/Q11**：jwt_secret 已配置；主题切换持久化；用户管理改角色/删除（409 保护文案）
8. **Q8①/D-1**：运行日志显示真实耗时；次日日志出现 prune_history 成功记录
