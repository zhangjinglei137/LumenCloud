> **说明**：本文档是对用户现有 n8n 体系 6 个流程的完整梳理（流程拓扑、节点职责、数据流、已知问题），

## 一、系统全景

### 1.1 六大流程一览

| 流程 | 触发方式 | 职责 |
|------|---------|------|
| `定时所有影视` | 每 1 小时 | 遍历 media 表全部影视，串行调用 `影视下载`；全部完成后轮询等 aria2 空闲再触发 `NasTools目录同步` |
| `影视下载`（核心） | 被 `定时所有影视` 调用 | 查 TMDB/Emby → 查遗漏集 → 网盘搜索（夸克）→ 提取缺失集 → 转存 → Aria 下载 → 写派发状态 → PushPlus 通知 |
| `清理夸克网盘` | 每 3 小时 | 等 aria2 空闲后清空 alist `/quark` 目录（夸克云盘中转空间），带新鲜度保护 |
| `NasTools目录同步` | 被 `定时所有影视` 调用 | 登录 → 重启 NasTools → 等待 → 重新登录 → 触发目录同步 → 记录同步时间 |
| `更新cloudSaverToken` | 被 `影视下载` 调用 | Redis 缓存 cloudSaver token，缺失时登录获取 |
| `sendPushPlus` | 被 `影视下载` 调用 | 读取 push_plus_token 并推送通知 |

### 1.2 完整数据流

```
夸克网盘分享链接
   │  cloudSaver /api/quark/save（转存到 quark_default_folder）
   ▼
「我的夸克网盘」（10G 容量，中转空间）
   │  alist 挂载为 /quark
   ▼
alist 取直链 /api/fs/get → aria2 下载到本地 /downloads
   │
   ▼
NasTools 目录同步 → 刮削入库 → Emby 可播放
   │
   ▼
定时清理 /quark（或转存前清理）→ 释放云盘中转空间
```

**容量约束**：夸克网盘仅 10G，转存文件为中转性质，下载完成后靠清理流程释放空间。

## 二、`影视下载` 核心流程详解（32 节点）

### 2.1 节点拓扑（当前版本）

```
开始（executeWorkflowTrigger）
 └→ 获取cloudSaverToken（子流程）→ 获取openListKey(Postgres) → 获取EmbyKey → 获取TMDB Key
     → 获取运行配置Raw(Postgres) → 获取运行配置(Code)
         └→ 从表中获取TMDBID(Postgres) → If（有 TMDBID?）
               ├─ true  → 获取EMBYID(HTTP: Emby Items, AnyProviderIdEquals=tmdb.<id>)   ← 有 tmdb_id 直查 Emby
               │           └→ 获取已派发集(Postgres) → If-媒体在Emby
               │                ├─ true（在 Emby，剧集模式）
               │                │   └→ 查看遗漏集(Emby Shows/Missing) → 过滤遗漏集
               │                │       └→ Aria2下载任务(HTTP 当前任务) → Aria2等待任务(轮询)
               │                │           └→ 解析遗漏集(Code，排除已派发/限批3集)
               │                │               └→ 获取网盘资源(cloudSaver /api/search)
               │                │                   └→ 提取分享码(Code) → 提取分享码信息(Code)
               │                │                       └→ 提取缺失集(Code，递归网盘匹配)
               │                │                           └→ 转存前清理(Code) → 转存(Code)
               │                │                               └→ Aria下载(Code)
               │                │                                   └→ 整理派发状态(Code)
               │                │                                       └→ 写入派发状态(Postgres)
               │                │                                           └→ Wait(10s) → 整理pushplus(Code) → 发送pushplus(子流程)
               │                └─ false（不在 Emby，全量模式）
               │                    └→ 获取网盘资源 → …（同一链路，提取缺失集走全量逻辑）
               └─ false → 获取TMDBID(HTTP: TMDB search/multi)                          ← 无 tmdb_id 先 TMDB 搜索
                           └→ If-TMDB有结果
                                ├─ true → Update rows(写回 tmdb id) → 从表中获取TMDBID → If（回环：重查 tmdb_id，此时走 true 分支）
                                └─ false → 获取网盘资源（走全量模式，**不经过 获取已派发集/If-媒体在Emby**）
```

### 2.2 关键节点职责与参数

| 节点 | 类型 | 关键逻辑 |
|------|------|---------|
| `获取运行配置` | Code | 读 config 表组装运行参数（cloudsaver_base_url / emby_base_url / aria2_rpc_url / quark_default_folder / tmdb_proxy 等） |
| `从表中获取TMDBID` | Postgres | 读 media 表 tmdb id |
| `获取TMDBID` | HTTP | `api.themoviedb.org/3/search/multi`，`If-TMDB有结果` 判定后 `Update rows` 回写 |
| `获取EMBYID` | HTTP | Emby `/Items` + `AnyProviderIdEquals=tmdb.<id>`；`If-媒体在Emby` 决定剧集/全量模式 |
| `查看遗漏集` | HTTP | Emby `/Shows/Missing`（需 Emby 未配置 provider 时 P11 误判全量） |
| `解析遗漏集` | Code | 单一来源（`过滤遗漏集`）→ 排除已派发集 → **限批 3 集**；`过滤遗漏集` 上游含 `Aria2下载任务`（已在下载中的剔除） |
| `获取网盘资源` | HTTP | cloudSaver `/api/search`（**✅ P4 已修复：executeOnce:true 已配置，同关键词只搜一次**） |
| `提取分享码` | Code | ✅ P5 部分修复：增加匹配条件（精确>前缀>子串）+ **限数 20 个**；注意：是条件匹配而非评分排序，误匹配风险未根治 |
| `提取分享码信息` | Code | 逐分享码调 `/api/quark/share-info`（间隔 500ms），`searched` 语义区分「无资源」与「搜索失败」 |
| `提取缺失集` | Code | 递归网盘目录匹配遗漏集；三重匹配（SxxExx/SxxExxx/第N集）；全量模式限批 `MAX_BATCH=3`、候选上限 `CANDIDATE_LIMIT=300`、`DISPATCHED_EXPIRY_MS=7天` |
| `转存前清理` | Code | ✅ 10G 应对：aria2 忙→`skipped:true` 本轮跳过；空闲→清空 /quark 后继续转存 |
| `转存` | Code | cloudSaver `/api/quark/save`（fids/fidTokens/folderId/shareCode/**receiveCode**——P7 语义待确认） |
| `Aria下载` | Code | alist 取直链 → aria2 addUri（GID）→ 返回 status/details |
| `整理派发状态` | Code | 组装 `episode_state:<media>` JSON（episode → {s,t} 状态） |
| `写入派发状态` | Postgres | **config 表 varchar(2000) 存 JSON（P2 未修复，长剧有截断风险）** |
| `整理pushplus` / `发送pushplus` | Code/子流程 | ✅ P1 已修复：`整理pushplus` 含短路（`status==='warning'` 或文件列表为空时 `return []`，不推送） |

### 2.3 防重 / 容错机制（现状）

- **防重双源**：Emby 查已有集（`查看遗漏集`）+ `episode_state` 派发状态（7 天过期重试）
- **searched 语义**：`提取分享码信息` 若全部请求异常则 `searched=false`，下游不标 unmatched、下轮立即重试
- **onError**：`获取网盘资源` / `Aria2下载任务` / `Aria2等待任务` / `写入派发状态` 已配 `continueRegularOutput`（✅ P6 部分修复），其余关键 HTTP 节点无兜底

## 三、其余 5 个流程详解

### 3.1 `定时所有影视`（11 节点）

```
定时(每小时) → 查询所有影视(Postgres: media 全表)
  └→ Call '影视下载'(串行, waitForSubWorkflow) → 获取aria2配置Raw → 获取aria2配置
      └→ 获取下载任务(HTTP: aria2 getGlobalStat) → If（numActive/numWaiting 为 0?）
            ├─ 空闲 → Call 'NasTools目录同步'
            └─ 忙 → 轮询计数器(Code: 最多20轮×3min=60min) → 是否超时
                  ├─ 未超时 → Wait(3min) → 获取下载任务（回环）
                  └─ 超时 → 终止（静默）
```

**特点**：每小时全量遍历（T1 未修复：无遗漏集也全链空跑）；全部影视完成后才同步 NasTools。

### 3.2 `清理夸克网盘`（12 节点）

```
开始(每3小时) → 获取aria2配置Raw → 获取aria2配置 → 获取Aria2下载详情
  → 判断下载是否空闲
      ├─ 空闲 → 获取文件列表(alist /api/fs/list /quark) → 检查文件新鲜度(Code)
      │         └→ 批量删除(alist /api/fs/remove)
      └─ 忙 → 轮询计数器 → 是否超时
            ├─ 未超时 → Wait(30s) → 回环
            └─ 超时 → 发送清理超时通知（✅ C2 已修复：超时不再静默）
```

**新鲜度保护（✅ C1 修复）**：`检查文件新鲜度` 检查 /quark 最近 5 分钟是否有文件变动，有则本轮跳过删除，避免误删刚转存未提交 aria2 的文件。

### 3.3 `NasTools目录同步`（9 节点）

```
开始 → 获取NasTools配置Raw → 获取NasTools配置
  → 登录NasTools(Code) → 重启(HTTP) → Wait(30s) → 登录NasTools1(Code)
  → 目录同步(HTTP) → 记录同步时间(Postgres)
```

**特点**：以「重启整个 NasTools 服务」方式强制刷新媒体库挂载（N1：下载频繁时被反复重启，靠调用方频率限制；N2：登录失败仅 throw，无告警）。

### 3.4 `更新cloudSaverToken`（8 节点）

```
When Executed → Redis(get cloudSaver token) → If（token 存在?）
  ├─ 存在 → 输出token
  └─ 不存在 → 获取cloudSaver配置Raw → 获取cloudSaver配置 → 登录(HTTP POST /api/user/login)
              → 存入token(Redis, TTL 7000s)
```

**特点**：token 缓存 7000s；Redis 故障无兜底（U1 未修复）。

### 3.5 `sendPushPlus`（3 节点）

```
开始 → 获取pushPlusToken(Postgres) → HTTP Request(POST + JSON body 传 token/title/content/template)
```

**特点**：✅ S1 已修复：HTTP POST + JSON body 传 token/title/content/template，无 URL 长度问题。

## 六、现状到新系统的演进要点

1. **容量约束是核心设计输入**：夸克 10G 中转空间 → 新系统「容量感知转存队列」+「下载完成即释放」取代定时清理
2. **21 个问题必须逐一被新架构吸收**：P2→独立 episode_state 表、P1→通知短路、N1→重启+冷却保留（用户确认重启为绕 NasTools bug 的必要手段）……
3. **`media` 表数据（11 部影视）迁移**，`episode_state` 不迁（防重靠 Emby 重新建立基线）
4. **外部服务语义**（cloudSaver 端点、alist /api/fs/*、aria2 RPC、NasTools 重启流程）在旧流程中是唯一权威参考，新系统沿用同一套 API 契约

详见 [`新系统设计.md`](./新系统设计.md)。
