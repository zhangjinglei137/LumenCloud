## 三、阶段 2：骨架（本次交付）

### 3.1 数据模型（10 张表，SQLAlchemy + Alembic）
- **Alembic 初始化**：补 `alembic` 依赖；`database.py::init_db()` 从 `create_all` 切换为 `alembic upgrade head`；`env.py` 用**同步 engine**（sqlite:// / postgresql://）跑 offline migration；**迁移脚本手写为主、autogenerate 仅辅助**（避免双后端出两份不同迁移）；`BigInteger + Identity` 在 SQLite 下验证不报错。
- 建表：`media / episode_state / transfer_queue / download_task / task_run / quark_capacity_log / users / invite_codes / watch_requests / notifications / system_config`（11 张，含 §3.3）。
- 关键约束落地：`episode_state.UNIQUE(media_id, episode)`、`transfer_queue.UNIQUE(media_id, episode)`、`idx_tq_status/idx_tq_media`、`idx_notif_recipient`。
- 原型环境启用 SQLite `WAL + foreign_keys=ON + busy_timeout`（database.py PRAGMA）。

### 3.2 服务层（方案 B）
- **完整实现**：
  - `tmdb`：`/3/search/multi` 搜索（tmdb_proxy 支持）
  - `emby`：`/Items`（AnyProviderIdEquals=tmdb.<id>）、`/Shows/Missing`、not-in-emby 二次模糊查询兜底（P11）
  - `cloudsaver`：login + **token 失效自动重登**（内存缓存，不落 DB）+ search + share-info（串行 500ms 间隔，全 async）+ save（receiveCode 参数见 Q3）
  - `alist`：`/api/fs/list`、`/api/fs/remove`、`/api/fs/get`（直链）
- **仅留签名 + 配置读取 + 异常框架**：`aria2`（addUri/tellStatus/getGlobalStat）、`nastools`、`pushplus`、`notifier`（InAppNotifier/PushPlusNotifier 接口 + NotifierChain）。
- `capacity_provider.check(candidate_bytes) -> bool`：先留接口 + 占位（`source=estimated`），Q1/Q2 回写后实现 A/B 模型；**fail-closed**：容量不可用一律不转存（保持 pending）；故障分支挂 `flow_error` 通知（防静默停滞）。

### 3.3 调度骨架（手动触发，不注册定时）
- AsyncIOScheduler 注册 5 个 job 但 **scan_all_media 不注册定时**（§12.2 阶段①「仅手动触发」），通过 `/api/media/{id}/scan` 触发；
- `process_transfer_queue` / `nastools_sync` 注册时加 **guarded 短路**（逻辑未实现则 `task_run(skipped)` 返回，避免 pending 无限堆积 / no-op 空转）；
- **`recover_on_boot()`** 补进 `main.py` lifespan（§4.1：扫描超时未完成 transferring/downloading 回退 queued）；
- `system_config` **双层开关**：全局总开关 + job 级开关；阶段 2/3 定时保持关闭（手动触发），阶段 3 验证后、阶段 4 上线时开启。
- 铁律保障：**GID 来源校验兜底保留简化版**——转存前发现陌生 aria2 GID 即本轮跳过并告警（10G 重复转存代价高）。

### 3.4 最小验证 API（3 个，含 DTO 脱敏）
- `POST /api/media/{id}/scan`：手动触发巡检验证搜索→入队链路；
- `GET /api/queue`：转存队列列表——**立即落实 §9.1 脱敏**（stoken/receive_code/fid_tokens/pwd_id/share_code/folder_id：guest 隐藏，admin 仅后 4 位），不直接返回表记录；
- `GET /api/capacity`：容量状态（used/total/source/checked_at + pending 队列预估占用，注明「pending=未消费积压，不代表真实占用」）。
- 其余全部 API（media CRUD、auth、approvals、settings、logs）留阶段 3。

### 3.5 巡检主流程（scan_all_media，搜索→入队，不转存）
```
状态预检(status=tracking) → Emby 已有集/缺失集(防重基线)
  ├─ 无遗漏 → task_run(skipped) → 结束
  ├─ Emby 故障 → fail-safe（仅处理既有 queued/failed-retry，暂停新缺集发现）
  └─ 有遗漏 → cloudSaver 搜索 → 加分匹配+限数20 → share-info
      → 大小过滤(剧集≤1.5G/电影≤5G，media 覆盖) → 三重匹配缺失集
      → 事务内「检查并写入」transfer_queue(pending)+episode_state(queued) → task_run
```

### 3.6 CI/CD
- 核验补全 `ci.yml`：backend 导入检查（现有）+ **Alembic 双后端迁移测试**（SQLite + Postgres 各跑一次 `alembic upgrade head`）+ 前端 vue-tsc/build（现有）+ trivy（现有）。
- `docker.yml` / `docker-branch.yml` 已存在，**不动**（Docker 构建留阶段 3）。

### 3.7 验收标准（阶段 2）
1. 本机 venv 起 `uvicorn app.main:app`，SQLite 建表成功（WAL/foreign_keys/busy_timeout 生效）；
2. 手动 scan 一部 media → 搜索→入队成功，`episode_state`=queued、`transfer_queue`=pending，无重复入队（幂等）；
3. Emby 故障模拟 → fail-safe 生效；无遗漏 → skipped 短路；
4. `/api/queue` 脱敏正确（guest 无敏感字段、admin 后 4 位）；
5. `/api/capacity` 返回 `source=estimated` 占位不报错；
6. `recover_on_boot`：人为造 transferring 超时记录 → 重启 → 回退 queued；
7. Alembic：SQLite 本地迁移成功；Postgres 用独立迁移测试库 dry-run 校验（不碰生产库）。
