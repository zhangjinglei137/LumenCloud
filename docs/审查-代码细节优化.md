## D. 长期运行维护

### D-1｜P2｜`task_run` / `quark_capacity_log` 表无清理机制（多数共识 glm+qw）

- **定位**：`backend/app/models/__init__.py:163-174`（task_run 表定义）；全局搜索确认无对应清理代码
- **证据**：`task_run` 每分钟至少 1 条（transfer job skipped），1 年约 **52 万条**；`quark_capacity_log` 每小时至少 1 条，1 年约 8700 条。
- **影响**：`/api/logs` 查询（含 LIKE + JOIN + ORDER BY）性能逐渐下降。
- **建议**：新增清理 job（保留最近 30 天 + 归档），或在 `logs.py` 强制时间范围过滤。运维手册补清理指引（见 `审查-文档与流程.md` G-1）。

### D-2｜P2｜logs 无时间范围过滤

- **定位**：`backend/app/routers/logs.py:19-68`
- **证据**：查询参数只有 `task_type/status/media_id/tmdb_id/title`，无 `started_after/started_before`。
- **影响**：长期运行后无法高效查看「最近 1 小时的错误」等常见运维场景。
- **建议**：增加 `started_after` / `started_before` 查询参数（ISO 格式）+ WHERE 条件，可配合 `_resolve_done_states` 性能。

### D-3｜P2｜`_alert_cooldown` 内存字典无上限增长

- **定位**：`backend/app/tasks/transfer.py:85`
- **证据**：
  ```python
  _alert_cooldown: dict[str, tuple[float, str]] = {}
  ```
  key 格式 `"{media_id}:{category}"`，每个 media 首次触发告警新增一个 key，过期 key 不清理。
- **影响**：100 个 media 全部触发过 ≈ 200 个 key，占用可忽略，但长期运行缓慢增长。
- **建议**：LRU dict（maxsize=500）或带 TTL 定期清理超过 `_ALERT_COOLDOWN_SECONDS * 2` 未命中的 key。

## E. 接口与 HTTP 层

### E-1｜P1｜`scan_media` 同步 await 阻塞 HTTP 请求 → 504（跨主题，见架构报告补充）

- **定位**：`backend/app/routers/media.py:419`、`backend/app/routers/approvals.py:169`
- **证据**：
  ```python
  # media.py
  task_run_id = await run_scan(media_id)   # 同步等待完整巡检
  # approvals.py
  await scan_media(media_id)               # 批准后同步等待巡检
  ```
- **触发路径**：admin 手动触发巡检 / 批准想看请求 → `scan_media` 同步执行完整巡检链路（Emby 基线 + cloudSaver 搜索 + share-info 串行 500ms 间隔 + share-list 递归遍历 + 入队），耗时可达**数分钟** → 前端/反向代理（通常 60-120s）超时 → 504；且 FastAPI 可能取消协程导致 scan 中途被取消、已入队任务不完整。
- **建议**：改为 fire-and-forget（类似 `scan.py` 内部 `_trigger_transfer` 的模式），立即返回 `task_run_id`，前端轮询 `/api/logs` 获取结果。

### E-2｜P2｜logs title 搜索未转义 LIKE 通配符

- **定位**：`backend/app/routers/logs.py:49`
- **证据**：
  ```python
  stmt = stmt.where(Media.title.ilike(f"%{title}%"))
  ```
- **触发路径**：搜索 `"100%"` → `ILIKE '%100%%'` 匹配所有含 "100" 的 title；搜索 `"_"` → 匹配所有 title（`_` 是单字符通配符）。
- **建议**：对 `%`、`_`、`\` 转义后拼入 LIKE，或改用 `func.position` / 应用层过滤。

### E-3｜P2｜`httpx.AsyncClient` 未复用连接池

- **定位**：`backend/app/services/emby.py:88`、`backend/app/services/alist.py:47`、`backend/app/services/aria2.py:72`（每次请求新建 client）；对照 `backend/app/services/nastools.py` 正确持会话（`_get_client`）
- **证据**：
  ```python
  # emby.py:88  每次请求新建/销毁 TCP 连接
  async with httpx.AsyncClient(timeout=timeout) as client:
      resp = await client.get(url, params=params)
  ```
- **影响**：无连接复用，Emby `/Shows/Missing` 实测 **7s+**，连接建立开销叠加。cloudsaver 已在 `_request` 内复用，但重试路径（`cloudsaver.py:149`）又新建 client。
- **建议**：对 emby/alist/aria2 采用模块级 `httpx.AsyncClient` 实例（惰性创建、连接池复用），类似 `nastools.NasToolsClient._get_client` 模式；注意 base_url/headers 差异，可收敛为公共 HTTP 封装。

## H. 安全

### H-1｜P2｜CORS `allow_origins=["*"]` + `allow_credentials=True`（三方共识）

- **定位**：`backend/app/main.py:70-76`
- **证据**：
  ```python
  app.add_middleware(
      CORSMiddleware,
      allow_origins=["*"],
      allow_credentials=True,
      allow_methods=["*"],
      allow_headers=["*"],
  )
  ```
- **影响**：当前前端同源直出（StaticFiles）下无害；但若未来分离部署或加反向代理跨域，浏览器规范不允许 credentials=true 时用通配符 origin，带凭据的跨域响应会被拒绝（且 Starlette 对该组合行为随版本变化）。JWT 走 Authorization 头不依赖 cookie，`allow_credentials=True` 实际无必要。
- **建议**：`allow_origins` 改为实际前端部署 origin 列表（环境变量注入，如 `["http://localhost:8000", "https://yourdomain.com"]`），或关闭 `allow_credentials`。

### H-2｜P2｜数据库密码硬编码弱密码 + db 日志无轮转

- **定位**：`docker-compose.yml:33`、`docker-compose.prod.yml:30`（密码 `"lumencloud"`）
- **影响**：prod 用弱密码；PostgreSQL 日志无轮转配置，长期运行可能占满磁盘。
- **建议**：prod 改用强密码（env 注入）；db 服务加 logging 轮转配置（max-size/max-file）。

### H-3｜P2｜JWT 改密不吊销已签发 token（多数共识 glm+qw）

- **定位**：`backend/app/routers/auth.py:178-179`（注释明确说明权衡）
- **影响**：改密后旧 token 仍有效至过期（168h = 7 天）。**自用产品可接受**（glm/qw 共识）。
- **建议**：可选 `users.token_version` 实现吊销；运维手册补 JWT 密钥轮换步骤（见 `审查-文档与流程.md` G-1.5）。

### H-4｜P2（自用可接受）｜`config_store` 全量缓存敏感键

- **定位**：`backend/app/services/config_store.py:72`
- **证据**：
  ```python
  _cache = {r.key: r.value for r in rows}   # 全量加载含敏感凭据
  ```
- **影响**：`_cache` 变量可被任何 import config_store 的模块直接读取（`config_store.get("emby_api_key")` 无需鉴权）。**当前自用可接受**；若未来多用户/对外部署需加鉴权或最小化缓存。

## I. 用户反馈 12 问题（代码/前端类，第二轮 2026-09）

> 详细分析见 `审查-用户反馈12问题.md`；本节收录 bug 与前端/UI/功能类条目。

### I-1｜P1｜bug｜转存队列页崩溃：`n.toFixed is not a function`（Q3）

- **定位**：`frontend/src/utils/format.ts:3-7`（`formatGb`）、`:16-23`（`formatBytes`）；调用点 `QueueView.vue:123,127,131,172,272`
- **根因**：`Number.isNaN("10")` 返回 `false`（不转换类型）→ 字符串通过守卫 → `"10".toFixed` 抛 TypeError → 整页渲染崩溃、列表瞬间消失。后端某数值字段为字符串或容量不可用时字段缺失/异常类型触发
- **建议**：① 前端 `formatGb`/`formatBytes` 入口 `typeof gb === 'number'` 守卫或 `Number(gb)` 强制转换（立即）；② 后端 `routers/capacity.py` unavailable 分支返回 `used_gb: None, total_gb: None`，所有数值字段序列化前确保 float；③ 随 C-3 修复 `/api/capacity` 复用模块级单例 provider

### I-2｜P2｜bug（显示误导）｜设置页 jwt_secret 永远显示「未配置」（Q5）

- **定位**：`backend/app/routers/settings.py:71-93`（`_services_configured` 对 jwt_secret 的判定）；对照 `backend/app/config.py:88-115`（`load_or_create_jwt_secret` 文件化自动生成）
- **根因**：DB 无 `jwt_secret` 键 → fallback 默认 `"change_me"` → 判定 False → **设置页永远显示「jwt_secret 未配置」**。实际 jwt_secret 首启自动生成落盘 `<data_dir>/.jwt_secret`（chmod 600），**仅用于签发/校验登录 JWT**，与用户密码无关（密码 bcrypt 存储）
- **建议**：① 修 `_services_configured`：jwt_secret 按文件存在性判定或从该判定中剔除；② 设置页加只读说明「已自动生成，无需配置；轮换=删除文件重启」；③ 「系统参数」区块改名「业务参数」加说明

### I-3｜P2｜bug｜运行日志耗时恒 0（Q8①）

- **定位**：`backend/app/tasks/__init__.py:39-58` `record_task_run`：`started_at=ts, finished_at=ts` 用同一 `_now()` → 差值恒 0；前端 `LogsView.vue:144-155` 用 `finished_at - started_at` 计算

### I-4｜P2｜bug｜消息/审批不显示用户名显示 id（Q10）
