# 影视下载两队列重设计（TaskQueue + DownloadQueue）

> 状态：设计草案（2026-09-07，经多轮决策确认，待实施前评审）
> 关联：docs/新系统设计.md（既有设计基线，本方案是其中「调度与队列设计」章节的演进版）
> 本方案基于对 n8n 旧流程 `n8n旧版备份/影视下载.json` 与 LumenCloud 现状实现的逐节点对比，
> 并结合 aria2 官方机制调研（on-download-complete / WebSocket / tellStopped）产出。

---

## 一、背景与问题定位

### 1.1 旧 n8n 流程 vs 当前实现的差异

| 维度 | n8n 旧流程 | LumenCloud 现状 | 差异结论 |
|---|---|---|---|
| 入队去重 | config 表 `episode_state:<media>` JSON（dispatched/unmatched，7 天过期） | episode_state 表 + UNIQUE(media,episode) | 现状更可靠 |
| 批处理粒度 | 每轮 ≤3 集（MAX_BATCH=3，system.multicall 批量推） | 串行单任务（全局锁） | 现状慢，无并发 |
| 容量检查 | 无（靠转存前清空 /quark） | 模型 B 硬上限：used+file+margin ≤ quota（fail-closed） | 现状有，单任务粒度 |
| 下载完成感知 | Wait(10s) + tellActive/tellWaiting 轮询 | tellStatus 轮询（分钟级 job） | 两者均为轮询，秒级事件驱动缺失 |
| **文件重命名** | **aria2 addUri 传 `out`=格式化名** | **`out=file_name`（夸克原始名，未格式化）** | **根因问题 ①** |
| 队列结构 | 单队列（config JSON） | 三表（episode_state/transfer_queue/download_task） | 职责重叠，需重构 |

### 1.2 已确认的三大根因问题

1. **下载不改名**：`backend/app/tasks/transfer.py:1105` 调 `aria2.client.add_uri(link, out=file_name)`
   时 `file_name` 是夸克分享原始名，未做格式化。n8n 旧流程用 `formatFileName` 把本地落盘名
   格式化为「剧名 - SxxExx - 第 X 集.ext」，Emby/NasTools 靠文件名里的 SxxExx 识别集数。
   → **修复方案：下载时 aria2 `out` 参数格式化（沿用 n8n 老办法）**。
   （原拟「转存后在 alist 上 fs/rename 改名再下载」，经议会 3 票一致反对——夸克落盘异步
   使改名时机难把握、rename 后 quark_path/清理跟踪需同步、失败重试需幂等——已改回 aria2 `out`。）

2. **状态卡死**：五节点状态机的超时回退未覆盖全部节点（recovery 只认
   `_REVERTABLE_NODES=('transfer','download','downloading')`，scrape/library 被排除），
   且 node 与 state 存在双写不一致风险。某节点卡住后无人推进。
   → **修复方案：超时回退覆盖全节点（含 scrape/library），状态机单源化**。

3. **重复下载/去重失效**：episode 键（SxxExx / 全量=文件名）与落盘名耦合处存在分叉风险
   （改名后文件名 ≠ 键）；done 态防重解除依赖 Emby 二次确认，存在窗口期。
   → **修复方案：防重键与落盘名严格分离，DownloadQueue 的 UNIQUE(media_id, episode) 为防重权威源**。

### 1.3 设计目标

- 两张独立表：**TaskQueue（任务队列/探测层）** + **DownloadQueue（下载队列/执行层）**，
  取代现有 episode_state / transfer_queue / download_task 三表。
- 下载并发由**容量预算 + 并行上限**驱动（上限默认 3，可调，见 §5.3）。
- aria2 **下载完成 hook 回调**事件驱动推进状态机（轮询降级兜底）。
- 完整人工控制面（暂停/恢复/置顶/取消/排序/手动加集/跳过/手动探测/重试）。

## 二、总体架构

```
┌──────────────────────────── 探测阶段（TaskQueue） ────────────────────────────┐
│                                                                              │
│  scan_all_media（定时）                                                        │
│   └─ Emby 遗漏集 → 过滤未播 → 按集入 TaskQueue(pending)                         │
│   └─ probe 执行器：cloudSaver 搜索 → 提取分享码 → share-info → 递归匹配文件       │
│        ├─ 找到 → ready（快照 file_size/share_code/fids/fidTokens/folderId）    │
│        ├─ 搜不到 → unmatched（静默 N 天自动重试）                               │
│        └─ 探测失败 → error（重试计数）                                          │
└─────────────────────────────────┬────────────────────────────────────────────┘
                                  │ 产出（promote：ready → DownloadQueue.pending）
┌──────────────────────────── 执行阶段（DownloadQueue） ────────────────────────┐
│                                                                              │
│  process_download_queue（容量预算并发）                                         │
│   ├─ 准入：used + Σ(预留) + 本文件 ≤ quota 才转存（否则 quota_wait）            │
│   ├─ 转存 transferring：cloudSaver save → 等落盘 → alist 直链                  │
│   ├─ 下载 downloading：aria2 addUri(out=格式化名, comment=lumencloud:<m>:<ep>) │
│   ├─ 刮削 scrape：NasTools force 目录同步（事件触发）                           │
│   ├─ 入库 library：Emby 收录确认 → done → 删夸克 → 释放容量预留 → 准入下一个     │
│   └─ aria2 hook 回调：/internal/aria2/notify 事件驱动推进（轮询兜底）            │
└───────────────────────────────────────────────────────────────────────────────┘
```

**事件流**：
- 转存/下载/入库各节点完成 → `_spawn` 续跑（事件触发）→ 兜底 job 定期补拉。
- aria2 下载完成 → hook 脚本 POST `/internal/aria2/notify` → 后端按 GID/comment 消歧
  → 推进 scrape 节点 + 触发 NasTools force 同步 → library 确认 → 删夸克 → 释放容量。
- tellStatus / tellStopped 轮询保留为**兜底**（事件丢失/断连补偿，recovery 超时回退不变）。

## 三、数据模型（两张表）

> 遵循全局约定：主键 `BIG_PK = BigInteger().with_variant(Integer, "sqlite")` + Identity；
> file_size 用 BigInteger（>2G）；默认值走 server_default；非注解 mapped_column 风格。
> 迁移用 alembic 手写脚本（对齐现有 versions/ 风格）。

### 3.1 task_queue（任务队列/探测层）

```python
class TaskQueue(Base):
    """缺失集探测任务（防重基线 + 探测结果快照）。

    防重权威源 = DownloadQueue.UNIQUE(media_id, episode)（本表为探测视图）。
    episode 键规则：剧集=SxxExx（S01E01，三位集数保留三位）；
    电影=「movie:<media.title>」归一化键（审阅 P1 修订：多版本匹配取一，防重复下载/同名覆盖）。
    """

    __tablename__ = "task_queue"
    __table_args__ = (
        UniqueConstraint("media_id", "episode", name="uq_task_queue_media_episode"),
        Index("idx_tq_status", "status"),
        Index("idx_tq_media", "media_id"),
        Index("idx_tq_silent_until", "silent_until"),
    )

    id = mapped_column(BIG_PK, Identity(), primary_key=True)
    media_id = mapped_column(BigInteger, ForeignKey("media.id"), nullable=False)
    episode = mapped_column(Text, nullable=False)          # S01E01 / 电影=movie:<title>
    # ---- 探测结果快照（ready 时填充，promote 时整体拷贝进 download_queue）----
    file_name = mapped_column(Text)                        # 夸克分享原始文件名
    file_size = mapped_column(BigInteger)                  # 字节；探测到才有
    share_code = mapped_column(Text)                       # 夸克分享码（12 位）
    pwd_id = mapped_column(Text)
    stoken = mapped_column(Text)
    receive_code = mapped_column(Text)
    fids = mapped_column(Text)                             # JSON 数组字符串
    fid_tokens = mapped_column(Text)
    folder_id = mapped_column(Text)
    # ---- 状态机 ----
    status = mapped_column(  # pending/probing/ready/unmatched/error/done
        Text, nullable=False, server_default=text("'pending'")
    )
    probe_attempt = mapped_column(Integer, server_default=text("0"))
    silent_until = mapped_column(DateTime)                 # unmatched 静默到期时间
    error = mapped_column(Text)
    created_at = mapped_column(DateTime, server_default=text("CURRENT_TIMESTAMP"))
    updated_at = mapped_column(DateTime, onupdate=func.current_timestamp())
```

### 3.2 download_queue（下载队列/执行层）

```python
class DownloadQueue(Base):
    """下载执行任务（防重权威源：UNIQUE(media_id, episode)）。

    承接旧 transfer_queue + download_task + episode_state 的职责：
      - 执行状态机（transferring/downloading/scrape/library）+ 全节点超时回退
      - aria2 GID / quark_path / local_path 跟踪
      - cloudSaver save 幂等（save_task_id / save_attempt_at）
      - 容量预留记账（quota_wait 不消耗 retry_count）
    """

    __tablename__ = "download_queue"
    __table_args__ = (
        UniqueConstraint("media_id", "episode", name="uq_download_queue_media_episode"),
        Index("idx_dq_status", "status"),
        Index("idx_dq_media", "media_id"),
    )

    id = mapped_column(BIG_PK, Identity(), primary_key=True)
    media_id = mapped_column(BigInteger, ForeignKey("media.id"), nullable=False)
    episode = mapped_column(Text, nullable=False)          # 防重键（同 task_queue）
    task_queue_id = mapped_column(BigInteger, ForeignKey("task_queue.id"))
    # ---- 分享信息快照（promote 时从 task_queue 整体拷贝，转存阶段独立）----
    file_name = mapped_column(Text, nullable=False)        # 夸克原始文件名
    file_size = mapped_column(BigInteger, nullable=False)  # 字节
    share_code = mapped_column(Text, nullable=False)
    pwd_id = mapped_column(Text)
    stoken = mapped_column(Text)
    receive_code = mapped_column(Text)
    fids = mapped_column(Text)
    fid_tokens = mapped_column(Text)
    folder_id = mapped_column(Text)
    # ---- 落盘名（aria2 out 参数；命名规则见 §七）----
    download_name = mapped_column(Text)                    # 格式化落盘名，addUri out 用
    # ---- 执行跟踪 ----
    aria2_gid = mapped_column(Text)                        # 来源标记 comment 同值
    quark_path = mapped_column(Text)                       # /quark/<真实名>（删除用）
    local_path = mapped_column(Text)                       # /downloads/<download_name>
    save_task_id = mapped_column(Text)                     # cloudSaver save 幂等标记
    save_attempt_at = mapped_column(DateTime)              # save 受理时间（超时兜底）
    # ---- 状态机（全节点可超时回退，见 §四）----
    status = mapped_column(  # pending/transferring/downloading/scrape/library/
        Text, nullable=False, server_default=text("'pending'")  #   quota_wait/done/skipped/failed
    )
    node_attempt = mapped_column(Integer, server_default=text("0"))
    node_started_at = mapped_column(DateTime)
    node_finished_at = mapped_column(DateTime)
    node_error = mapped_column(Text)
    retry_count = mapped_column(Integer, server_default=text("0"))
    quota_reject_count = mapped_column(Integer, server_default=text("0"))
    error = mapped_column(Text)
    enqueued_at = mapped_column(DateTime, server_default=text("CURRENT_TIMESTAMP"))
    updated_at = mapped_column(DateTime, onupdate=func.current_timestamp())
```

**防重语义**：
- `UNIQUE(media_id, episode)` 是防重权威源。入队（promote）用「事务内 SELECT + 冲突捕获」，
  与现状一致；`done` 后到 Emby 二次确认入库前仍视为已处理（防重复下载窗口期），
  Emby 确认解除防重后重新参与遗漏检查。
- **防重键与落盘名分离**：episode 永远是 SxxExx（或电影 `movie:<title>` 归一化键），
  `download_name` 只是 aria2 落盘名。改名永不回写防重键 → 根治「改名导致键分叉 → 去重失效」。
- `skipped` 也是防重终态（审阅 P0 修订）：人工跳过某集后写 DownloadQueue(status=skipped)，
  防 scan 重新入队（§8.2）。

## 四、状态机设计

### 4.1 TaskQueue（探测）

```
                  ┌────────── 静默到期自动恢复（silent_until ≤ now）──────────┐
                  ▼                                                          │
pending ──探测──▶ probing ──找到──▶ ready ──promote──▶ done（产出后即终态）
                  │  ├───────────── 搜不到 ──▶ unmatched ──静默 N 天──────────┘
                  │  └───────────── 失败 ──▶ error（probe_attempt++，≤3 自动重探 / 超限人工）
```

- `unmatched`：`searched=true` 且确实无资源时标记（沿用 n8n searched 语义：探测异常不算
  unmatched，立即重探）。静默期 `silent_until = now + N 天`（N 默认 2，system_config
  `task_queue_unmatched_silent_days` 可调）。到期后自动恢复 `pending` 重新探测。
- `ready`：探测拿到 file_size 与分享信息快照。**大小过滤在此完成**（剧集 >max_episode_size_gb
  或电影 >max_movie_size_gb → 不入 ready，记 error「超大小上限」供展示）。
- promote 条件：TaskQueue=ready 且 DownloadQueue 同 (media, episode) 不存在
  （防重 + 幂等）；promote 后 TaskQueue→done。

### 4.2 DownloadQueue（执行）

```
queued/pending ──转存──▶ transferring ──提交aria2──▶ downloading ──hook/轮询──▶ scrape
     │                        │                          │                     │
     │                        └──── 失败（确定性/超时）──▶ failed ◀── 超时回退 ──┘
     └── 容量不足 ──▶ quota_wait（quota_reject_count++，不消耗 retry_count）
                          └── 容量释放后自动恢复 pending

scrape ──NasTools force 同步──▶ library ──Emby 收录确认──▶ done（终态）
   │                              │                            │
   └── 同步失败（node_attempt++） ─┘── Emby 未收录（node_attempt++）──▶ failed（≥3 人工）

任何非终态 ──人工跳过──▶ skipped（防重终态，不再探测/下载，§8.2）
```

- **全节点超时回退（修复状态卡死）**：recovery 的 `_REVERTABLE_NODES` 扩展为
  `('transferring','downloading','scrape','library')`。**阈值分级（审阅 P0 修订）**：
  transferring/downloading 沿用 `episode_state_timeout_hours`（默认 2h）；
  **scrape 独立阈值（默认 4h）**；**library 独立阈值（默认 ≥6h，
  `library_revert_timeout_hours` 可调）且回退前先做一次 Emby 收录确认——已收录不回退**
  （防 Emby 慢收录被误杀 → 重复转存/重复占容量；与 library_check 600s 轮询口径解耦）。
  回退 → pending + retry_count++；`retry_count ≥ 3` → failed（人工 retry 重置）。
- **quota_wait 不消耗 retry**：与现状 quota_reject 语义一致；`quota_reject_count ≥ 5`
  触发 flow_error 告警（沿用 P3-2 节流）。
- **done 语义**：Emby 确认入库（library_check 集级确认）→ done → 删夸克 → 释放容量预留。
  done 后防重仍保持，直到 Emby 二次确认解除（见 §三防重语义）。

## 五、容量记账（容量预算并发）

### 5.1 准入规则

```
准入转存 ⇔  used(实时) + Σ(reserved) + file_size + 安全余量 ≤ quota
```

- `used`：alist `/quark` 递归统计（现有 capacity.provider.get_usage，30s 进程内缓存）。
- `reserved`：已准入未释放的在途任务预留和（见 5.2）。模型 B 公式从「单文件」推广为
  「单文件 + 在途总和」——这就是用户确认的「容量说了算，几个任务能把容量跑满就同时跑几个」。
- **准入并发模型（审阅 P0 修订）**：`reserved` 唯一可信源 = **DB 聚合**（DownloadQueue 中
  `status ∈ (transferring,downloading,scrape,library)` 行的 `file_size` SUM）。准入在
  **同一事务内** `SELECT SUM(file_size) ... FOR UPDATE` + 状态条件更新原子完成
  「读用量 + 记预留」，杜绝多 worker 并发双双过检突破硬上限（现状 transfer.py 的
  `_process_lock` 仅单 worker 部署下有效，降级为性能缓存，**不依赖其保证并发正确性**）。
- 容量数据不可用 → fail-closed（不准入，quota_wait）。

### 5.2 预留生命周期

```
promote（pending）                转存准入             Emby 确认 + 删夸克
     │                               │                        │
     │         未准入不预留           ├── 计入 reserved ────────┼── 释放 reserved
     ▼                               ▼                        ▼
  TaskQueue.ready           DownloadQueue.transferring     DownloadQueue.done
```

- **释放点 = 删夸克**（不是下载完成）：夸克空间从「转存落盘」占用到「入库删夸克」才释放，
  期间该文件同时占夸克 + NAS 本地盘。
- **释放触发点全集（审阅 P0 修订）**：reserved 随任一「离开 in-flight 集合」的转移同步
  释放——①删夸克（done）；②任一节点 → failed（确定性失败/超时回退）；③人工 cancel；
  ④任务被清理/GC。漏释放 = 容量永久占用 → 后续任务永久 quota_wait。
- **记账实现**：reserved 以 DB 聚合为准（见 5.1），进程内账本仅作单 worker 部署的
  加速缓存；**DB 重算兜底**（启动 recover_on_boot 与每小时 recover_stale 时按
  in-flight 状态行重算，消除进程重启丢账）。
- 容量不足：当前任务转 quota_wait，**轮询/事件续跑**（释放后自动准入下一个）。
- reserved 趋势（预留和/可用预测）随容量快照一并写 `quark_capacity_log`（P2 演进）。

### 5.3 并发与节流

- **并行上限（审阅 P1 修订，覆盖原「无硬上限」决策）**：容量预算只防夸克空间爆，不防
  cloudSaver API 限流 / aria2 连接数 / NAS IO。`download_queue_max_concurrent` 默认 **3**
  （对齐 n8n MAX_BATCH=3；system_config 可调，0=不限）。用户原意「容量说了算」由容量
  预算保证：**同时准入数 = min(max_concurrent, 容量可容纳数)**。
- **转存串行化保留**：cloudSaver save 侧仍加进程内锁（save 是 API 受理，本身很快；
  等落盘是轮询，可并发等待）。下载 addUri 可并发。
- 现有 GID 来源校验（`comment` 前缀 `lumencloud:`）保留，防 n8n 误启动双转存。

## 六、aria2 下载完成回调（事件驱动）

### 6.1 机制（librarian 权威调研结论）

- **`--on-download-complete` 是全局 hook，无法按任务指定**（aria2 RPC options 不含 hook）。
  notify.sh **只透传 `$1=GID`**（审阅 P1 修订：脚本不做 RPC 反查，避免脚本侧持 token /
  多一跳网络）；后端按 `DownloadQueue.aria2_gid` 反查任务，`comment` 仅作 GID 来源
  校验辅助。
- 部署（p3terx/aria2-pro）：脚本放 `/config/script/`，aria2.conf 加
  `on-download-complete=/config/script/notify.sh`；容器内脚本需能出网访问后端。
- 备选 WebSocket 事件（aria2.onDownloadComplete）可作冗余，但断连丢事件且不重放，
  必须配 tellStopped 补偿——本方案**不单独依赖 WS**。

### 6.2 回调链路

```
aria2 下载完成
  └─ notify.sh（aria2 主机，$1=gid）
       └─ POST http://<backend>/internal/aria2/notify
            Headers: X-Aria2-Signature = HMAC-SHA256(body, internal_aria2_webhook_secret)
            Body: {"gid": "<gid>", "status": "complete"}
                 └─ 后端校验签名 → 按 DownloadQueue.aria2_gid 反查（comment 仅供 GID 来源校验）
                      └─ 幂等校验（仅 downloading→scrape 推进，防重复回调）
                           ├─ 推进 node=scrape → 触发 NasTools force 同步（nastools_sync(force=True)）
                           ├─ 状态双写 download_name/local_path 落库
                           └─ download_complete 通知照旧（notifier：站内 + PushPlus）
```

- **鉴权**：`internal_aria2_webhook_secret` 存入 system_config（settings 默认值 + env fallback），
  HMAC-SHA256 签名校验 + 时间戳防重放（±15min，放宽防后端重启/积压误拒；重复推进由
  幂等校验兜底）。
- **兜底**：现有 tellStatus/tellStopped 轮询保留（job 兜底 + recovery 超时回退不变）。
  事件丢失 → 轮询补偿推进；回调与轮询并发推进 → 条件更新幂等（见 4.2）。

### 6.3 通知时机清单

| 时机 | 事件 | 说明 |
|---|---|---|
| addUri 成功（进入 downloading） | download_started | 沿用现有事件，新增触发点 |
| 下载完成（downloading→scrape，hook 或轮询） | download_complete | 沿用现有 |
| 首次 unmatched（该集搜不到资源） | flow_error | 「X 集未找到，将静默 N 天」；静默期内节流不重复（审阅 P1 修订） |
| quota_wait 持续 >1 天 | flow_error | 「容量不足已持续 X 天」；quota_reject_count ≥5 告警沿用 |
| 任一节点失败达上限 → failed | flow_error | 沿用现状 |
| scrape/library 超时回退 | flow_error | 沿用现状（回收重试语义） |

### 6.4 部署清单（aria2 主机侧）

1. 写 `/config/script/notify.sh`（curl POST，`--max-time`，失败静默防阻塞）。
2. aria2.conf 追加 `on-download-complete=/config/script/notify.sh`。
3. 容器内验证到后端网络可达；签名密钥在后端设置页配置。

## 七、命名规则（aria2 out 格式化）

- **剧集**（文件名含 SxxExx）：`{media.title} - {SxxExx} - 第 {N} 集.{ext}`
  （n8n 格式；media.title 为 TMDB 校正名）。
- **电影/全量模式**：`{media.title}.{ext}`（用户确认：统一格式化，去掉夸克杂乱分享名）。
  **防重键归一化（审阅 P1 修订）**：电影 episode 键 = `movie:<media.title>`（而非原始
  文件名）——探测匹配到的多个版本（不同分辨率/来源）取一个（大小上限内），落盘名唯一，
  **杜绝多版本重复下载 + 同名互相覆盖**。
- **匹配不到 SxxExx 的剧集文件**：保持原名（n8n fallback 行为，不误改）。
- 实现：`transfer.py` 的 addUri 调用改传 `out=download_name`（`download_name` 由
  `_format_download_name(file_name, media)` 生成并落库到 DownloadQueue）。**quark 网盘文件不动**，
  防重键（episode）不参与格式化 → 根治去重分叉。
- SxxExx 正则对齐 n8n：`/(S\d+)E(\d+).*\.([^.]+)$/i`，三位集数（E100）保留。

### 9.1 数据迁移（alembic 一次性脚本）

- `episode_state`（node ∈ transfer/download/downloading 且 state ∈ transferring/downloading）

## 十一、风险与备选

| 风险 | 缓解 |
|---|---|
| 高并发压垮 cloudSaver/夸克 API | `download_queue_max_concurrent` 默认 3（可调，0=不限） |

## 十二、NaSTools Webhook 集成（2026-09-08 追加）

### 12.1 背景

NasTools 目录同步（现有 `nastools_sync.py` 登录→重启→目录同步，绕 bug 的 n8n 契约）把 aria2
落盘文件整理进 Emby 媒体库后，本系统靠 `library_check` 轮询 Emby 确认入库。jxxghp 的
**Webhook 插件**（插件市场内置，作者 jxxghp）可监听 NaSTools 内部事件总线（EventType 全集），
事件发生时向第三方地址 POST —— 把「轮询等 Emby」升级为「NaSTools 整理完成 → 主动通知我们」。

### 12.2 事件与 payload（lib-2 权威调研结论）

- 插件：`app/plugins/modules/webhook.py`，WebUI「设置→插件市场」启用，配置请求方式(POST/GET) + Webhook 地址。
- POST 模式 body JSON 顶层只有两个字段：
  ```json
  {"type": "<event_type>", "data": { ... }}
  ```
- 相关事件（EventType 字符串值）：`transfer.finished`（整理完成）、`transfer.fail`（整理失败）、
  `download.fail`（下载失败）、`subscribe.finished`（订阅完成）、`media.scrap.start` 等。
- **`transfer.finished` 的 data 结构**（filetransfer.py:907 触发）：
  ```json
  {
    "in_path": "...", "file": "...", "target_path": "...",
    "dest": "<最终媒体库文件完整路径>",
    "media_info": {"tmdb_id": 12345, "title": "...", "media_type": "Movie/TV",
                   "season": [], "episode": [], "year": "2024", ...}
  }
  ```
- **鉴权限制**：旧版插件 POST **不支持自定义 Header**（仅 Content-Type）→ 不能 HMAC 签名；
  鉴权方案二选一：① Webhook 地址带 query token（`http://backend/internal/nastools/notify?token=xxx`），
  ② 新版「消息通知→Webhook」渠道（支持 `Authorization` Header 静态 token）。
  本设计采用 **query/header 静态 token**（`internal_nastools_webhook_token`，system_config 优先，
  env `NASTOOLS_WEBHOOK_SECRET` fallback；旧版插件用 query、新版渠道用 Header，端点两者都认）。

### 12.3 端点设计：`POST /internal/nastools/notify`

- 挂载：与 aria2 notify 同层（`/internal` 前缀，不经 /api，见 routers/api.py P6 模式）。
- 鉴权：secret 缺失 → 503（fail-closed）；`?token=` query 或 `X-NaSTools-Token`/`Authorization` header
  与 secret 常数时间比较，不匹配 → 401。
- 事件分派（仅处理关注事件，其余记录后返回 ok）：
  - `transfer.finished`：解析 `data.media_info.tmdb_id` / `title` → 按 tmdb_id 反查本系统
    `media` 行（无则忽略）→ **触发该 media 的入库推进**：对 `download_queue` 中该 media
    的 `status='scrape'` 行推进为 `library`（NasTools 已整理完成，即刮削步骤完成）→
    fire-and-forget 触发 `library_check`（Emby 入库确认 → done + 删夸克 + 释放容量）。
    幂等：仅 scrape→library 条件更新；重复回调/无匹配行 → 幂等跳过。
  - `transfer.fail` / `download.fail`：flow_error 通知（站内 + PushPlus，节流沿用）。
  - 其它 type：忽略（返回 `{"ok": true}`）。
- 兜底：事件丢失不影响主链路（`library_check` 轮询照旧 + recovery 超时回退照旧）；
  回调仅加速「NasTools 完成 → 入库确认」这一段。

### 12.4 配置清单

| 项 | 位置 | 说明 |
|---|---|---|
| `internal_nastools_webhook_token` | system_config（优先）/ env `NASTOOLS_WEBHOOK_SECRET` | 端点鉴权 token |
| Webhook 插件 | NaSTools WebUI → 设置 → 插件市场 → Webhook | 地址填 `http://<backend>/internal/nastools/notify?token=<token>`（或新版渠道 Authorization） |
| 推送事件 | 插件默认推送全部 EventType（不可筛选） | 端点侧按 type 白名单忽略无关事件 |
