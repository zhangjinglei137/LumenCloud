# 审查报告 ② 文档与流程

> 审查基准：成熟自用产品化（长期运行 / 可能给别人用 / 数据不能丢 / 出问题能快速定位）
> 审查方式：三方 councillor（ds / glm / qw）独立审读 + council 共识合成
> 本文件覆盖主题：G 文档与运维（含各席位文档相关发现 B1-B4 / D1-D4 的合并）
> 另见：`审查-架构与设计逻辑.md`、`审查-代码细节优化.md`、`审查-待办清单.md`

---

## 总体评价

文档整体质量高、与代码注释形成良好呼应，但存在一个结构性缺陷：**「设计文档」偏向历史蓝图、「运维手册」偏向速查，两者对当前真实运行状态（哪些开关实际开着、配额实际值、哪些 job 需要手动 API 开启）缺乏单一可信来源**。设计文档描述的运行闭环（§4.2/§4.4）与实际实现存在断层，运维手册排障条目指向了错误/不完整的开关。新接手者按文档操作会出现「按文档配置了却完全不生效」的死胡同。

## G-1｜P2｜运维手册关键缺口（多数共识，三方各有贡献）

`docs/运维手册.md` 缺失以下场景的处置步骤：

### 1. 定时任务启用步骤清单（ds）
作为「阶段 4 冷切换已上线」的关键动作，文档没有一份可执行的「启用哪些 job、每个 job 的 `scheduler.<id>` 值、如何验证已生效」清单。§12.2 的切换清单只写到「`scheduler_enabled=true`」为止——而实际上这**不够**（见架构报告 A-2：job 级开关默认全关）。

### 2. `quark_quota_gb=210` 落地位置未提示（ds）
- 设计文档 §6.3 提到「当前部署设为 210，默认值仍为 10」；
- 但运维手册 §3 凭据表里只写「`quark_quota_gb`（默认 10）」；
- **后果**：生产部署若不改为实际空间，模型 B 会以 **10G 硬上限误拒 2G+ 大文件转存**。这是「文档与真实运行状态不一致」的典型。

### 3. 端到端验收清单缺失（ds）
现有文档是「设计蓝图 + 运维速查」，缺少从零部署 → 配凭据 → 开定时 → 添加一部剧 → 验证转存/下载/入库的逐步验证路径（`阶段1验证报告.md` 是阶段性实证，非操作手册）。

### 4. `task_run` / `quark_capacity_log` 清理指引（glm）
手册未提及这两张表会无限增长（`task_run` 每分钟至少 1 条，1 年约 52 万条），长期运行影响 `/api/logs` 查询性能。需补充清理策略（如手动 DELETE 30 天前记录，或预期中的清理 job）。

### 5. 排障场景缺失（qw）
- **数据库备份验证**：§4 只给备份命令，无恢复验证步骤（"备份不验证 = 没有备份"）；
- **`paused` + `downloading` 死锁处置**：架构报告 B-1 的问题当前无手动修复路径，只能直接 SQL UPDATE，手册无说明；
- **JWT 密钥轮换**：删除 `.jwt_secret` 后重启会生成新密钥 → 所有已签发 token 失效，无说明；
- **alembic 迁移失败处置**：`init_db` 在 lifespan 中执行，若 `alembic upgrade head` 失败 → 启动失败，手册无对应排障步骤。

## G-2｜P2｜建议增加「当前部署状态卡」（ds）

在运维手册中增加一节，展示 `system_config` 里**生效的关键键值**（尤其 `scheduler.*` 各 job 开关、`quark_quota_gb`），排障时一眼可见实际配置。与架构报告 A-2（双层开关）联动——否则「开了总开关却不生效」这类问题无法从文档层面自查。

## G-3｜P2｜设计文档与代码偏差（多数共识）

| 偏差 | 定位 | 说明 |
|------|------|------|
| §4.2 列 5 个 job，代码实际注册 **7 个** | `docs/新系统设计.md` §4.2 vs `backend/app/scheduler.py` | 多出 `recover_stale` 和 `capacity_alert` 两个 job，scheduler.py 注释已更新但设计文档未同步（glm） |

| `notification_scan` 间隔、容量安全余量公式待确认 | — | 设计值与实现关系未核对（qw，待确认项） |

**建议**：文档与实现双向同步；公式确认后落文档；或在文档头部标注「以代码为准，文档为设计参考」。

## G-4｜P2｜通知事件无汇总文档（glm）

通知事件（`download_complete` / `flow_error` / `approval_pending` / `download_started`）分散在各代码文件，无汇总。建议运维手册补充通知事件触发表：什么事件 → 什么条件 → 通知到谁 → 去重键（与架构报告 A-3 关联）。

## G-5｜P2｜recovery 任务行为说明缺失（glm）

运维手册 §6.3 提到「超时回退」但未说明：
- recovery 每小时运行一次；
- 2h 超时阈值可配（`episode_state_timeout_hours`）；
- **副作用**：会移除 aria2 任务和夸克残留（修复架构报告 B-3 后需同步更新副作用顺序说明）。

## G-6｜P2｜第二轮用户反馈相关排障/UX 条目（2026-09）

> 详细分析见 `审查-用户反馈12问题.md`；本节仅收录文档/运维/UX 相关部分。

### G-6.1｜转存无 success 排障条目（Q1/Q8，高优先级）

运维手册需补充：**「转存后页面无 success、aria2 无任务 → 先验 `quark_default_folder` 是否等于 alist Quark 驱动 `root_folder_id`」**。这是 Q8 现象（转存成功但链路中断）的根因排障入口，且报错文本本身已引导用户核对（`transfer.py:137-139`）。同时补充「转存成功但 aria2 无任务」的排障步骤：检查 alist 直链是否可用、aria2 RPC 是否可达。

### G-6.2｜jwt_secret 说明（Q5，关联 G-2/H-4）

运维手册补充 JWT 密钥说明：自动生成落盘 `<data_dir>/.jwt_secret`（chmod 600），**无需配置**；用途仅登录 JWT 签发/校验（与用户密码无关，密码 bcrypt 存储）；轮换 = 删除该文件后重启（旧 token 全部失效）。设置页「系统参数」区块需改名「业务参数」并加说明文案（影响范围：扫描频率/容量阈值/超时行为）。

### G-6.3｜设置页邀请码 UX（Q6）

设置页分享码区增加：复制按钮、复制注册链接（`/register?code=xxx`，注册页需支持 query 预填）、使用者显示用户名（后端 JOIN users）、时间用 `formatTime` 格式化。

### G-6.4｜主题/容量显示（Q7/Q9，纯前端 UX）

容量百分比放大（MainLayout 圆形进度 width 30→40）；主题切换作为功能需求后置（CSS 变量收敛 + 切换 + localStorage 持久化），无文档流程影响，仅当实施时更新前端说明。
